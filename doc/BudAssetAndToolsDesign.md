# BudEngine Multi-Level Asset Pipeline & Toolchain Design

## 1. Overview

BudEngine uses a multi-level asset pipeline architecture.

Core principle:

> Source Asset is not Runtime Asset. Asset is transformed through multiple intermediate representations optimized for different stages.

Pipeline:

    Source Asset
        |
        v
    Raw Asset Data
        |
        v
    Internal Asset Data
        |
        v
    Runtime Asset Data
        |
        v
    GPU Resource

Design goals:

- Runtime engine remains lightweight.
- Expensive processing happens offline.
- Runtime only consumes optimized data.
- Asset format is independent from source format.
- Multiple runtime representations can coexist.
- Offline tools do not depend on runtime systems.

# 2. Asset Representation Layers

## 2.1 Source Asset

External authored data.

Examples:

- FBX
- OBJ
- glTF
- PNG
- TGA
- Material files

Characteristics:

- Created by artists.
- Depends on external format.
- Not optimized.
- Contains unnecessary information.

Example:

    chair.fbx

---

## 2.2 Raw Asset Data

Generated by AssetImporter.

Pipeline:

    Source Asset
        |
        v
    AssetImporter
        |
        v
    Raw Asset

Purpose:

Preserve source information after parsing.

Examples:

RawMesh contains:

- Original vertices.
- Original indices.
- Submesh information.
- Material references.
- Texture references.
- Skeleton information.
- Animation information.

Example:

    chair.rawmesh

Characteristics:

- Close to source data.
- Independent from external file format.
- Serializable.
- Cacheable.
- Useful for debugging.

Raw Asset represents:

"Parsed source data."

---

## 2.3 Internal Asset Data

Generated from Raw Asset.

Pipeline:

    Raw Asset
        |
        v
    Internal Asset

Purpose:

Provide engine canonical representation.

Internal Asset is no longer source oriented.

Example:

InternalMesh:

    Vertex Data
    Index Data
    Mesh Sections
    Material Slots
    Bounding Information
    Asset Metadata

Example structure:

    InternalMesh

        vertices
        indices
        sections
        bounds

Characteristics:

- No FBX/OBJ/glTF dependency.
- Used by all builders.
- Stable engine representation.
- Optimized for processing.

Internal Asset represents:

"Engine side editable data."

---

## 2.4 Runtime Asset Data

Generated by Builders.

Pipeline:

    Internal Asset

          |
          +----------------+
          |                |
          v                v

    Mesh Builder    Virtual Geometry Builder

          |
          v

    Runtime Asset

Examples:

### Traditional Mesh Runtime Data

    Vertex Buffer
    Index Buffer
    Mesh Sections
    Material Slots

### Virtual Geometry Runtime Data

    Cluster Data
    Hierarchy DAG
    Page Data
    Streaming Metadata
    Compressed Geometry

### Runtime Material Data

    Shader ID
    Texture Handle
    GPU Parameter Data
    Descriptor Index

Output:

    chair.budasset

Runtime Asset represents:

"GPU ready data."
